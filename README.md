# OpenFront 공격 계산기 v4.2.3

커서 위치에 대한 수소 혼합·원자 집중 공격을 비교하고, 검증된 계획을 `I`로 실행하는 사설·연습 로비용 유저스크립트입니다. v3의 고정 `원자 200 + 수소 1` 블록 대신 개별 사일로와 SAM 상태를 사용하는 계산기를 연결했습니다.

## 설치와 사용

1. Tampermonkey에서 기존 버전을 끄거나 교체하고 `openfront-x50-salvo-v4.2.3.user.js`를 설치합니다. 여러 버전을 동시에 켜지 마세요.
2. 게임 탭을 새로고침하고 커서를 목표에 잠시 멈춥니다.
3. 표시창에서 두 방식의 예상 명중 수·발사 수량·비용·궤적 방향을 확인합니다.
4. `I`를 한 번 누르면 목표를 고정하고 새 상태로 분석·재검증한 뒤 추천 계획을 실행합니다. 검증된 수소 혼합 계획이 우선이고, 없으면 검증된 원자 집중 계획을 선택합니다.
5. `Esc`는 계산과 아직 보내지 않은 발사를 취소합니다. 이미 보낸 요청과 날아가는 미사일은 취소하지 못합니다.
6. `F8`로 사일로·SAM의 좌표, 레벨, 준비 수량, 계획 참여 여부를 펼칩니다. 상세창 안에서 스크롤할 수 있습니다.

`수소 혼합 추천`, `원자 집중 추천`, `현재 탐색 범위에서 돌파 어려움`, `계산 미완료`, `판정 불가`를 구분합니다. **추천은 현재 상태에 대한 예측이며 명중 보장이 아닙니다.** 발사 요청의 게임 반영과 목표 도달 확인을 구분하며, 발사를 모두 보낸 뒤에도 이번 공격의 비행을 관측합니다.

기존 수동 단축키 H/G/J/M/Z/V/X/N은 유지됩니다. 새 계산기는 `I`와 표시창을 담당하며, 추천 공격 실행 중에는 이 스크립트의 다른 발사·건설 단축키를 막습니다. 기존 수동 작업이 진행 중이면 먼저 Esc로 끝내야 합니다.

## 긴 계산과 자동 재검증 — v4.2.3

이전에는 I 탐색을 약 4초에서 끝냈고, 발사 전 검증이 2틱(0.2초)을 넘으면 상태가 그대로여도 결과를 거부했습니다. 이제 I는 Worker에서 **정해진 후보들을 끝까지 탐색**합니다. 후보 사이에서 진행 수를 보내고 잠시 실행을 양보하며, 검토한 후보와 궤적 캐시를 유지합니다. 모든 가능한 배치·시각을 무한 탐색한다는 뜻은 아닙니다. 표시창의 자동 미리보기는 게임 부담을 줄이기 위해 기존 짧은 예산을 유지하며, 미완료를 불가능으로 표시하지 않습니다.

- I 탐색 및 발사 전 검증에는 고정된 벽시계 마감 시간이 없습니다. 후보 수·경과 시간을 표시하고 Esc로 취소할 수 있습니다. 같은 목표의 긴 계산을 시간 초과로 처음부터 반복하지 않습니다.
- 단순히 틱이 지났다는 이유로 검증을 버리지 않습니다. 목표·규칙·사일로·SAM·상대적인 재장전 시각·업그레이드 진행을 비교합니다. 이 조건이 같으면 시간의 원점을 옮겨 검증 결과를 사용할 수 있습니다.
- 조건이 달라지면 같은 후보를 최신 상태로 재검증합니다. 통과하지 못하면 새 후보를 탐색합니다. 다시 I를 누를 필요가 없습니다. 긴 계산 후에는 공식 가격을 다시 조회하며, 조회 중 취소도 유지합니다.
- 발사 중 재계산이 시간 부족으로 미완료면 남은 발사를 보류하고 350→700→1,400ms처럼 예산을 늘려 최신 비행 상태에서 다시 계산합니다. 이 단계는 움직이는 미사일 때문에 새 상태에서 계산하며, 발사 전 탐색처럼 과거 상태의 탐색을 그대로 이어가지 않습니다.
- 반복 변경 12회에서 무조건 중단하던 기본값은 해제했습니다. 공격 시작 후 관측 한도 1,200틱(현재 규칙 120초), 누적 원자·수소 한도, 실제 명령 반영 확인과 Esc 취소는 유지합니다. 관측 시간이 끝나면 이유를 표시하고 남은 발사를 멈춥니다.

**SAM 15% 증가를 가정해도 모든 15% 이내 변경을 보장하지는 못합니다.** 같은 총 슬롯이라도 위치·레벨·사거리·재장전·요격 순서가 다르고, SAM 한 기 추가와 기존 SAM 레벨업은 효과가 다릅니다. 이번 버전은 가상의 15% 여유만으로 상태 검증을 생략하지 않고 실제 변경 후의 후보를 다시 검사합니다. 목표 위치를 바꾸면 경로, 사일로 선택 순서와 도착 시각도 달라져 다시 계산해야 합니다.

**전송 속도와 실제 출발 속도는 다릅니다.** 기존 Z는 여유가 있을 때 최대 50발씩 초당 10건, 즉 500발의 발사 요청을 보냅니다. I는 검증한 일정에 따라 기본 2틱(0.2초) 간격으로 한 요청을 보내므로 연속 원자 요청 기준 최대 약 250발/초입니다. 수소 삽입·계획 간격·재계산·요청 한도·발사관 부족은 더 늦춥니다. 원본 서버의 분당 150건 제한도 있으므로 500발/초를 계속 유지하는 구조가 아닙니다. 같은 사일로는 틱당 한 발씩 출발하므로 실제 미사일 출발은 사일로 배치와 대기열에도 좌우됩니다. I를 500발/초로 바꾸지는 않았습니다.

추가 검증: 후보 탐색 재개와 동기 탐색 결과 일치, 시간 원점 이동과 실제 타이머 변경 구분, 7초 지연 계산, 0.8초 발사 검증, 검증 중 SAM 업그레이드 후 자동 재계산, 재검증 중 Esc, 발사 중 계산 예산 확대 및 수소 누적 한도 유지를 확인합니다. 지연·시간 초과 브라우저 검사는 지연 주입을 사용하며 공개 서버 성능 측정은 아닙니다. v4.2.3으로 원본 전체 클라이언트도 로컬 실행해 실제 유료 가격 조회·발사·SAM Lv1→Lv3 비행 중 강화·자동 재검증 1회·수소 도달을 확인했습니다.

## N 군함 연속 배치 — v4.2.2

N을 한 번 눌러 배치 모드를 켜고 바다를 클릭합니다. 기본값은 **클릭마다 10척 추가**입니다. 다섯 번 빠르게 클릭하면 50척이 하나의 대기열에 쌓이고, 각 클릭 때의 위치를 저장해 순서대로 처리합니다. 군함은 게임 규칙에 따라 같은 수역의 항구에서 만들어져 선택 위치로 이동합니다. 클릭 위치에 즉시 생성되는 것은 아닙니다.

이전에는 클릭마다 독립적인 타이머를 만들고 예약 전송 직전 한도를 다시 검사하지 않아, 연타 시 요청이 겹칠 수 있었습니다. 이제 한 요청씩 전송하고 그 군함의 실제 생성·순찰 목표를 확인한 후 다음 요청을 보냅니다. 전송 직전에는 공유 초당·분당 한도를 재확인하며, 한도 부족 시 **남은 수량을 버리지 않고 기다렸다가 이어서 보냅니다**.

- 화면에서 요청한 수량, 게임 생성 확인 수량, 남은 척수·묶음, 현재 배치 목표를 구분합니다.
- 매 요청 전 공식 buildables 응답으로 가격과 해당 수역의 건조 가능 여부를 확인합니다. 골드 부족·사용할 항구 없음·조회 실패에서는 이유를 표시하고 남은 대기열을 중단합니다.
- **N은 배치 모드만 켜고 끕니다. 대기열 취소는 Esc**입니다. 이미 보낸 요청은 취소할 수 없습니다. 탭을 숨기거나 게임이 바뀌어도 남은 요청을 중단합니다.
- 한 건의 생성 반영을 5초 동안 확인하지 못하면 중단합니다. 늦게 도착할 요청을 중복 전송하지 않습니다. 건조 요청 완료와 실제 생성 확인을 같은 뜻으로 표시하지 않습니다.
- 군함 대기열이 남아 있으면 I 자동 공격은 시작하지 않습니다. 화면은 군함 진행 상황을 표시하고 불필요한 커서 공격 재분석도 멈춥니다.

검증은 군함 대기열 단위 검사 10개와 브라우저 입력 검사 3개를 추가했습니다. 빠른 5회 클릭의 50척 순차 반영, 위치 고정, 한도 회복 후 전체 수량 유지, Esc·늦은 비동기 응답 취소, 골드 부족, 게임 변경과 생성 미확인 중단을 확인합니다. 원본 UnitView의 군함 순찰 목표 조회도 검사합니다. 군함을 공개 온라인 서버에서 대량 건조한 검증은 아닙니다.

## 읽기 쉬운 표시창 — v4.2.1

- 결론 → 이유 → 다음 행동 순서로 읽습니다. 수소+원자 공격과 원자만 쓰는 공격의 발사 수량·예상 도달 수를 별도 행으로 비교합니다.
- 같은 위치를 자동 재분석할 때 이전 결과를 지우지 않습니다. 화면 아래에 `재계산 중 · 직전 결과`만 표시하고 완료되면 교체합니다. 커서를 옮긴 경우 이전 결과에는 `이전 위치`와 좌표를 명시합니다.
- `준비 1관`은 `재장전 완료 1발분`으로 풀어 썼습니다. SAM 개수는 `지도 전체에서 SAM N기 검토`로 표시합니다. 이 숫자는 목표 주변의 SAM 개수가 아닙니다.
- 긴 계산 근거, 발사 한도, 비용·궤적·시간, 사일로/SAM 좌표와 오류 상세는 F8에 모았습니다. 명령 전송량은 작은 보조 정보로 표시합니다.
- 결과 갱신과 공격 실행 검증은 유지됩니다. I는 최신 상태로 다시 계산하고 검증되면 발사합니다. `미리보기에서 아직 확인 못했습니다`는 불가능 판정이 아니며, `돌파 계획을 찾지 못했습니다`도 탐색한 후보에 대한 결과입니다.

브라우저에서 느린 재계산 중 제목·비교 행 유지, 커서 변경 시 이전 위치 구분, 상세 스크롤 유지, 390px 폭 및 작은 화면, 새 오류 발생 시 이전 추천 가림을 확인합니다.

## 계산 최적화 — v4.2.0

궤적의 좌표, 틱 간격, SAM 사거리·표적 우선순위, 네 가지 검증 경우와 탐색 후보 순서는 유지했습니다. 계산 횟수를 줄이기 위해 다음 중복만 제거합니다.

- 매 SAM이 매 틱 전체 미사일을 훑던 부분을 공간 격자 조회로 바꿨습니다. 원본의 **탐지 반경 600**까지 후보를 모으고 정확한 거리로 다시 거릅니다. 요격 사거리 150만으로 잘라내지 않습니다. 동점 표적 순서도 기존 미사일 생성 순서로 복원합니다.
- 같은 좌표·방향·속도·맵 높이·요격 가능 구간의 경로를 재사용합니다. 사일로 대기열의 출발 시각은 바뀌었을 때 계산하고 연속 발사는 누적 갱신합니다.
- 화면 상태를 읽을 때 전체 유닛 목록을 한 번 조회해 종류별로 나눕니다. 비행 중 방어 변화 감지는 남은 경로의 정확한 범위를 캐시합니다.
- 기존에도 성공 계산에 넣지 않았던 다른 공격의 미사일은 Worker로 긴 경로를 복사하지 않습니다. 화면의 전체 관측과 비행 수 표시, 이번 공격의 추적은 유지합니다.

이전 v4.1.2 코드를 독립적인 비교 기준으로 보존했습니다. 무작위 배치 160개 × 처리 순서 4개 × 보수 모드 2개 = **1,280회**에서 명중·실패 수량, 사용 사일로, 발사·출발 시각, SAM별 요격 결과를 전체 비교했습니다. 완료된 탐색 결과, 경로 캐시 재사용, 관측 서명과 Worker 전달 데이터 축소도 대조합니다. 테스트한 입력에서 결과가 같다는 검증이며 모든 게임 상태에 대한 수학적 증명은 아닙니다.

동일한 합성 배치에서 원자 N발 뒤 수소 1발을 보내는 **고정 계획 한 번**을 시간 제한 없이 끝까지 계산한 결과입니다. 같은 컴퓨터의 Node v26.7.0에서 각 5회 교차 측정한 중앙값이며, 게임 FPS나 전체 추천 탐색 시간이 아닙니다.

| 사일로 / SAM / 원자 | v4.1.2 | v4.2.0 | 속도 |
| --- | ---: | ---: | ---: |
| 4 / 20 / 100 | 25.15ms | 17.66ms | 1.42배 |
| 20 / 100 / 500 | 593.51ms | 240.03ms | 2.47배 |
| 80 / 400 / 2,000 | 9,591.13ms | 3,486.72ms | 2.75배 |

2,000발의 남은 경로를 확인하는 방어 변화 감지는 캐시 준비 후 평균 약 10.85→0.64ms였습니다. 밀집 SAM 배치의 350ms 탐색은 개선 후에도 시간 제한에 도달했습니다. **SAM과 미사일이 한 구역에 몰리면 여전히 계산량이 커집니다.** 계산을 생략해 성공으로 처리하지 않고, 끝까지 검증되지 않은 계획은 실행하지 않습니다. 원본 SAM 표적 선택기는 그대로 사용합니다.

재현: `npm run benchmark`. 성능 비교에는 이전 코드와 새 코드의 전체 출력 일치 검사도 포함됩니다.

## 가격 조회 호환성 수정 — v4.1.2

`판정 불가 · r.unitsOwned is not a function`은 서버용 가격 함수에 화면용 PlayerView를 넘겨 발생하던 스크립트 오류입니다. 게임 화면에서 제공하지 않는 `unitsOwned()`를 호출하지 않고, 게임 UI와 같은 `buildables` 비동기 조회로 원자·수소 단가를 읽습니다. 조회 결과는 캐시하고 I 실행 직전에 다시 확인합니다. 가격이 없거나 조회가 실패하면 임의의 기본 가격·무료 가격으로 대체하지 않습니다. 조회 도중 Esc를 누른 뒤 응답이 와도 공격을 실행하지 않습니다.

HUD의 요청 한도는 공격 분석 성공 여부와 별개입니다. 초당·분당 여유가 있어도 분석 오류가 있으면 I 추천 공격을 실행할 수 없습니다. v4.1.2에서 가격 조회를 수정했고, v4.2.0에서 아래 계산 최적화를 추가했습니다.

## X 업그레이드 요청 소모 수정 — v4.1.1

기본 설정에서 X + 클릭 한 번은 일반 구조물 +500(50씩 **10건**), 사일로 +300(50씩 **6건**)입니다. V는 일반 구조물 +50, 사일로 +30이며 각각 1건입니다. 업그레이드 묶음 크기를 원자탄 `CFG.amount`와 분리해 발사량 설정을 바꿔도 업그레이드 요청 수가 늘지 않습니다.

같은 구조물의 전송·반영 대기 중 중복 클릭과 대상 조회 중 중복 작업을 막습니다. 키를 길게 눌러도 무장 상태를 반복 전환하지 않습니다. Esc는 무장을 해제하고 아직 전송하지 않은 업그레이드를 취소하며, 탭을 숨기거나 떠날 때도 예약 전송을 취소합니다. 이미 서버에 보낸 요청은 되돌릴 수 없습니다.

업그레이드는 기본적으로 1초에 최대 6건을 보내므로 +500은 **6건 + 다음 창 4건**으로 나뉩니다. 두 시간 창에 걸쳐도 총 소모는 10건입니다. HUD의 초당·분당 숫자는 다른 발사까지 합친 스크립트 전체 요청 수입니다. 시작 알림에는 해당 업그레이드의 예정 요청 수를 표시합니다. 분당 여유가 적을 때도 남은 여유보다 큰 묶음을 보내지 않습니다.

## 무엇을 계산하나요?

- 게임과 같은 고정 소수점 베지어 경로, 위/아래 방향, 맵 경계, 미사일 종류별 속도와 요격 가능 구간.
- 맨해튼 거리 순의 준비된 사일로 선택. 같은 사일로의 발사 대기열, 현재 점유 슬롯, 한 틱에 하나씩 회복되는 사일로 재장전.
- **SAM마다 별도 슬롯·대기열·레벨·업그레이드 사거리**. 목표 근처 밖의 SAM도 전체 목록에서 검사합니다.
- 원본 게임의 SAM 미래 요격 지점 계산, 표적 점수, 수소 가산점, 중복 요격 방지 및 재장전.
- 원자만 보내는 계획과 원자 사이/뒤에 수소를 넣는 계획. 두 방향과 여러 발사량·간격을 탐색합니다. 미리보기는 짧은 시간 예산, I는 후보 탐색 완료까지 계산합니다.
- SAM 처리 순서, 이동 처리 순서, 수소 요청 시각 ±2틱을 바꾼 네 경우에서 명중 조건을 확인합니다. 이는 확률 모델이나 성공률 수치가 아닙니다.
- 골드, 무기 비활성화, 팀 건물 피해 제한, 준비된 발사관, 명령 한도.

표시와 실행은 같은 계획 객체를 사용합니다. 계산은 Web Worker에서 실행하고, 발사 직전에 새 상태로 재검증합니다.

## 발사 중 자동 대응 — v4.1

게임 상태가 갱신되는 매 틱(현재 규칙 100ms)마다 사일로, 경로에 영향을 줄 수 있는 SAM의 추가·제거·레벨·업그레이드 상태, 이번 공격의 비행 상태를 확인합니다. 무관한 먼 SAM의 변화는 발사를 방해하지 않습니다.

1. 변화가 감지되면 **아직 보내지 않은 발사를 보류**합니다. 이미 보낸 요청은 실제 생성된 미사일과 대조한 다음 재계산하므로 중복 발사하지 않습니다.
2. 변경 후에도 남은 계획이 유효한지 먼저 검증합니다. 필요하면 발사량·방향·간격·사일로 선택을 다시 시뮬레이션합니다.
3. 수소탄이 이미 비행 중이면, 새 원자탄이 요격 시간에 맞춰 먼저 도달할 수 있는지 계산합니다. 수소 목표를 달성할 보완 계획이 있으면 원자탄을 추가합니다. **이미 날아간 수소탄의 경로나 출발 시각은 바꿀 수 없습니다.**
4. 수소 보완 계획이 없고 원자 명중 조건을 달성할 계획이 있으면 원자 집중으로 전환합니다. 전환 후 수소 혼합으로 되돌아가지 않습니다.
5. 후보 탐색을 마쳐도 유효한 계획을 찾지 못하거나 관측 시간·누적 발사량·사용자가 지정한 재계산 한도에 도달하면 남은 발사를 중단합니다. 이미 날아간 미사일은 계속 비행합니다.
6. 중단 후에는 다음 공격을 따로 시험해 재장전 대기 또는 `사일로 (좌표) Lv현재 → Lv후보`를 표시합니다. 시험한 레벨업에서도 해결되지 않으면 사일로 수·배치·발사 한도 검토를 안내합니다. **자동 건설·업그레이드를 수행하지 않습니다.** 제시 레벨은 성공한 시험 후보이며 최소 필요 레벨이나 업그레이드 비용을 증명한 값은 아닙니다.

기본 한도는 **이번 공격 전체에서 원자 최대 2,000발, 수소 최대 1발**입니다. 재계산할 때 한도가 리셋되지 않습니다. 재계산 최초 예산은 350ms이고 미완료 시 늘립니다. 기본 수정 횟수 제한은 없으며, 전체 공격 관측 한도는 1,200틱입니다. 계산 중 추가 변화가 생기거나 예정 시각이 지나면 낡은 결과를 실행하지 않습니다. 발사 반영 대기나 계산 동안에는 남은 발사가 보류되므로 지연 없이 실시간 대응을 보장하는 것은 아닙니다.

발사를 모두 보낸 뒤에는 `비행 관측 중`으로 표시합니다. 게임의 목표 도달 상태가 확인된 경우에만 도달 확인으로 표시하고, 미사일이 사라졌다는 이유만으로 성공 처리하지 않습니다. Esc, 탭 숨김, 게임 변경, 읽을 수 없는 비행 정보, 장시간 미반영 요청은 중단 조건입니다.

## 진단과 한계

- 발사관 부족, 특정 SAM의 수소 요격 위치·시각, SAM 재장전 후 반복 요격, 발사 시간 분산을 표시합니다. 이것은 시험한 계획의 실패 원인입니다. 특정 위치에 사일로를 추가하면 반드시 성공한다거나 최소 필요 레벨을 증명하지는 않습니다.
- 기본 명중 목표는 **수소 1발 또는 원자 1발**입니다. 두 무기의 피해량이 같다는 의미가 아닙니다.
- **이번 공격에서 발사·반영을 확인한 미사일만** 재계산에서 남은 궤적·대기 시간과 함께 사용합니다. 이 미사일은 이미 구매한 것으로 처리하고 골드·발사관을 다시 차감하지 않습니다. 공격 시작 전에 날아가던 미사일이나 다른 플레이어의 미사일은 방어를 대신 소모해 준다고 가정하지 않습니다. 현재 관측된 SAM 재장전 대기열은 반영합니다. SAM에 배정된 요격은 즉시 성공한 것으로 간주하고, 원자 폭발 이후에도 SAM이 남아 있다고 계산합니다. 따라서 실제로 가능한 공격을 놓칠 수 있습니다.
- 변경된 방어는 관측 후에 대응하므로 미래의 건설·업그레이드·동맹 변경, 관측되지 않은 명령, 서버의 실제 명령 수신 시각은 완전히 알 수 없습니다. 서버 SAM이 이미 캐시한 미래 요격 예약 전체도 클라이언트에 공개되지 않으므로 동일 상태의 완전한 서버 복제는 아닙니다. 화면의 현재 상태와 서버 실행 사이에 차이가 생길 수 있습니다.
- 후보 탐색은 유한합니다. `돌파 어려움`은 지정한 발사량·시간·후보 범위에서 계획을 찾지 못했다는 뜻입니다. `계산 미완료`이면 I에서 더 긴 계산 시간을 사용합니다. 비용 최적해를 보장하지 않습니다.
- 게임 내부 API를 사용합니다. 필요한 큐·업그레이드 상태가 없거나 확인한 사거리/틱 규칙이 다르면 값을 추측하지 않고 발사를 보류합니다. 온라인 배포판은 참조한 GitHub 커밋과 다를 수 있습니다.

## 설정

게임 콘솔에서 `__x50.planner.settings`를 수정할 수 있습니다.

```js
__x50.planner.settings.minAtomHits = 5; // 원자 집중의 목표 명중 수 (기본 1)
__x50.planner.settings.maxAtoms = 3000; // 이번 공격 전체 원자 한도 (기본 2000, 최대 5000)
__x50.planner.settings.maxHydros = 1; // 이번 공격 전체 수소 한도 (기본 1; 0이면 원자만)
__x50.planner.settings.adaptiveBudgetMs = 350; // 발사 중 첫 재계산 예산; 미완료 시 자동 확대
__x50.planner.settings.maxReplans = 12; // 선택 설정: 반복 변화 시 중단할 수정 횟수 (기본 Infinity)
__x50.planner.settings.budgetMs = 2500; // 표시창 계산 시간 (기본 1800ms)
__x50.planner.analyze(); // 분석만 수행
__x50.planner.inspect(); // 전체 상태와 선택/실패 계획 진단
__x50.planner.state(); // 실행 단계, 수정 이력, 종료 결과와 조언
__x50.planner.stop(); // 계산·실행 중단
```

I는 탐색 후보를 끝까지 계산하고 발사 전에 최신 상태에서 검증합니다. 시간만 지났다고 거부하지 않으며, 실제 타이머·배치가 바뀌면 자동 재검증합니다. Esc로 중단할 수 있습니다.

## 개발과 검증

Node 24 이상. 빌드 시 TypeScript를 사용하며 배포 스크립트는 외부 JS/CDN에 의존하지 않습니다.

```sh
npm ci --ignore-scripts
npm test
npm run test:browser
node scripts/verify-upstream.mjs /path/to/OpenFrontIO
node scripts/verify-client.mjs /path/to/OpenFrontIO
npm run verify -- /path/to/OpenFrontIO
```

브라우저 테스트는 Chrome이 필요합니다. macOS 기본 경로 이외에는 `CHROME_PATH`를 지정하세요. `SCREENSHOT_DIR`를 주면 검증 화면 이미지를 저장합니다.

배포 전에는 `npm run verify -- /path/to/OpenFrontIO` 한 명령으로 빌드 → 단위/회귀 → 원본 클라이언트 API → 원본 엔진 실행 → 공격 브라우저 흐름 → 업그레이드 브라우저 흐름 → 표시창 안정성 → 군함 대기열 검사를 모두 실행합니다. 어느 단계라도 실패하면 실패 상태로 종료합니다. 참조 엔진 커밋이 다르거나 원본 체크아웃이 없으면 검증을 생략하지 않고 중단합니다.

검증 범위:

- 원본 `Config`, `PlayerView`, `UnitView`, `GameView`, `PlayerImpl`의 해당 메서드를 직접 실행하는 **클라이언트 연결 검사 12개**. 이전 가격 호출의 `unitsOwned` 오류 재현, 수정된 공식 가격 경로, 호스트 전용 무료 가격, SAM 업그레이드·재장전, 팀 제한, 바다와 발사 지점의 SAM, 클라이언트 비행 위치, 요격 배정, 도달 상태를 확인합니다. 지도와 Worker 통신은 최소 어댑터이며 전체 웹 클라이언트를 구동한 검증은 아닙니다.

- 계산기·적응 실행 회귀 테스트 **65개**: 경로, 발사관 큐, 거리 순서, SAM 재장전, 수소 우선순위, 자원·비활성화·시간 제한 등.
- Chrome 모의 게임 통합 테스트 **17개**: 실제 Blob Worker 계산, I 발사 이벤트, 목표 고정, Esc 취소, SAM 강화 후 원자 보완, 요격 배정 후 원자 전환, 누적 수소 한도, 도달 관측, 중단 후 조언, 계산 중 취소, 반복 변화의 낡은 결과 폐기, 골드 부족, 지원하지 않는 상태, 좁은 화면 표시.
- 원본 게임의 Nuke/SAM/SAMMissile/MissileSilo 실행 클래스와 경로 클래스를 최소 지도·플레이어 어댑터에서 실행한 **130개 시나리오**. 이 중 추천된 **87개 계획**은 원본 실행에서도 명중 조건을 달성했습니다. 추가로 **비행 중 SAM 업그레이드 24개 시나리오**를 검증했고 24개 수정 계획이 명중 조건을 달성했습니다(수소 보완 4개, 원자 전환 14개 포함). 원본 엔진의 비행 인덱스·출발 대기 시간과 클라이언트에서 복원한 값도 대조했습니다. 영토 파괴는 착탄 계수로 대체하므로 전체 게임이나 실제 서버 테스트는 아닙니다.

참조 엔진: `openfrontio/OpenFrontIO` 커밋 `5dc09dbd2dde5105d8b403d7b5ddf8d503e04ec2`. v4.2.0 검증에서는 로컬 Vite 개발 서버와 GPU를 사용하는 Chrome에서 원본 전체 화면·게임 Worker·LocalServer를 실행했습니다. 실제 지도에서 유료 가격 조회, 바다 커서의 I 수소 발사·도달, 적 SAM Lv1과 아군 사일로 Lv10의 원자+수소 공격·도달을 확인했습니다. 비행 중 적 SAM을 Lv3으로 올린 별도 사례에서는 변화 감지 후 1회 재검증하고 추가 발사 없이 수소 도달을 확인했습니다. 이 전체 클라이언트 사례가 모든 적응 분기를 검증한 것은 아닙니다. SAM 사례는 로컬 시작 설정에 두 번째 플레이어를 추가하고 방어자 건설 명령만 테스트용 턴에 주입합니다. 화면·가격 API·미사일 이동·요격·폭발을 모의 구현으로 교체하지 않습니다. 공개 온라인 서버 및 Tampermonkey 확장 설치 과정의 종단 간 검증은 포함하지 않습니다.

`src/legacy.js`는 기존 수동 기능의 기반, `src/planner.mjs`는 순수 계산기, `src/adaptive.mjs`는 비행 복원·재계획·레벨업 후보 시험, `src/prices.mjs`는 공식 비동기 가격 조회, `src/browser.js`는 상태 수집·표시·실행, `src/vendor/`는 원본 경로/SAM 표적 선정 코드입니다. 루트의 일반 파일과 현재 버전 `.user.js` 파일은 `npm run build`로 생성합니다. 이전 v4.0.0·v4.1.0 배포본은 보존합니다.

### 원본 전체 클라이언트 확인

GPU 지원 Chrome과 실행 중인 **로컬** 원본 클라이언트가 필요합니다. 참조 체크아웃에서 의존성 설치 후 `GAME_ENV=dev npm run start:client`로 시작합니다. 이번 환경은 원본의 엔진 버전 제한과 달라 설치할 때만 `npm ci --ignore-scripts --engine-strict=false --no-audit --no-fund`를 사용했습니다. 원본 게임 코드는 수정하지 않았습니다.

```sh
npm run test:live             # 실제 바다 목표 / 유료 가격 / I 발사 / 도달
npm run test:live -- --sam    # 실제 적 SAM 방어 / 혼합 공격 / 도달
npm run test:live -- --sam --upgrade # 비행 중 실제 SAM 레벨업 / 재검증
```

기본 주소는 `http://127.0.0.1:9000`이며 `LOCAL_CLIENT_URL`로 바꿀 수 있습니다. 이 테스트는 localhost 외의 주소를 거부합니다. 처음 접속한 언어가 한국어·영어인 UI를 지원합니다. `SCREENSHOT_DIR`로 실제 비행 중 화면을 저장합니다. 전체 클라이언트 테스트는 일반 모의 브라우저 테스트와 별도로 실행하며 GPU가 없을 때 통과로 취급하지 않습니다.
